active request, deterministic generation, persistent multi-turn conversations,

## Findings

1. The 3.5 bpw artifact completes fresh and persistent workloads through the
   requested 256K context envelope without an allocation or API failure.
2. Decode throughput falls sharply as the active KV context grows, from about
   182 tok/s at 1K to about 15 tok/s at 256K.
3. Reconstructing chat history is not equivalent to retaining session KV. The
   128K persistent-turn TTFT is 1.45 seconds, over seven times the 200 ms target.
4. Qwasar therefore needs explicit resident session state and backend-reported
   reuse counters; client-side `previous_response_id` compatibility alone is
   insufficient for the coding-agent latency target.

## Instrumentation Correction

This run was emitted before the harness stopped inferring physical prefix reuse
from logical conversation length. Ignore `reused_prefix_tokens` in this run's
raw `samples.jsonl`. The schema now records that field as `null` whenever a
backend does not report the counter directly.
